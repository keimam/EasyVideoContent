Cadangan yang didukung minimal `gemini`, `groq`, `deepseek`, `openrouter`. Penyedia lain yang sudah didukung adapter boleh ditambahkan.

- Penyedia tanpa key otomatis dilewati, dengan catatan di log (tanpa menampilkan key).

## G2 — Logika failover
Bungkus pemanggilan LLM longform (satu titik masuk, mis. `call_llm_with_failover`) sehingga **semua** fitur AI longform memakainya.
- **Pindah langsung ke cadangan** untuk: kuota harian (`LLMDailyQuotaError`), kredit habis (`LLMCreditError`), key ditolak (`LLMAuthError`), model tidak ada (`LLMModelNotFoundError`).
- **429 per menit:** ikuti retry/tunggu yang sudah ada. Bila masih gagal, pindah ke cadangan.
- **Respons kosong / JSON tidak valid** (lihat G3): coba ulang di penyedia yang sama sesuai G3. Bila tetap gagal, pindah ke cadangan.
- Penyedia yang kena kuota harian ditandai **dijeda sampai reset** (simpan per proses + persist ringan di folder data, dengan waktu reset: OpenRouter 00:00 UTC; untuk penyedia lain gunakan jeda konservatif bila waktu reset tidak terverifikasi). Penyedia itu tidak dicoba lagi di batch berikutnya.
- Penyedia yang key-nya ditolak dijeda sampai key berubah.
- Bila semua penyedia gagal: lempar error yang sudah ada (perilaku fallback non-AI FA2.1 tetap berlaku), dengan pesan merangkum alasan per penyedia.

## G3 — Respons kosong dan JSON rusak
- Untuk panggilan yang mengharapkan JSON (Konteks Visual, penyusunan adegan, kata kunci AI): bila respons kosong atau JSON tidak valid → (1) ulang sekali dengan instruksi singkat "return JSON only" dan reasoning diminimalkan memakai mekanisme yang **sudah ada** di adapter untuk OpenRouter; (2) untuk penyusunan adegan, bila masih gagal, **pecah batch** (15 → 5 shot) dan ulang per bagian; (3) baru pindah ke cadangan.
- Bila kamu menambah parameter API baru untuk mengatur reasoning/max tokens, wajib sertakan URL dokumentasi resmi + kutipan ≤15 kata + waktu akses di Final Report.
